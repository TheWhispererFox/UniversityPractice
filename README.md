# University Practice — Delivery Drone

Учебная 3D-игра на Godot и C#. Заключительная практика: доставки, интерфейс, локальная статистика и проверки.

## Запуск

Используйте **Godot 4.7.2 .NET** (Mono) и .NET SDK с поддержкой `net8.0`
(проект проверен с SDK 9.0.300).

1. Откройте `project.godot` в Godot .NET.
2. Соберите C# проект кнопкой Build или командой `dotnet build UniversityPractice.sln`.
3. Нажмите F5: откроется главное меню. Start Game запускает уровень; Exit закрывает приложение.
   F6 на `Main.tscn` позволяет отдельно запустить игровой уровень с HUD.

## Управление

| Клавиша | Действие |
| --- | --- |
| W / S | Вперёд / назад относительно дрона |
| A / D | Влево / вправо относительно дрона |
| Q / E | Поворот влево / вправо вместе с камерой |
| Space | Подъём |
| Shift | Снижение |
| R | Перезапуск сцены, в том числе после поражения |
| 1 / 2 / 3 | Easy / Normal / Hard; начинает новую попытку |

Привязки используют физические клавиши и работают независимо от раскладки.
При отпускании клавиш дрон плавно тормозит и переходит к зависанию.
Жёлтая полоса обозначает переднюю сторону корпуса.

## Реализовано

- Одна замкнутая тестовая 3D-площадка с полом, потолком, стенами и препятствиями.
- Аркадный полёт `CharacterBody3D`: разгон, торможение, вертикальное движение,
  поворот и ограничение диагональной скорости. Гравитация компенсирована зависанием.
- Камера от третьего лица на `SpringArm3D`: приближается при препятствии позади дрона.
- Физические столкновения с окружением через `MoveAndSlide`.
- Независимый `PlayerHealth`: 100 HP, сигналы изменения здоровья и смерти.
- Урон при нормальной скорости удара выше 6 м/с:
  `ceil((скорость удара - 6) * 5 * множитель сложности)`. Горизонтальная скорость ограничена 12 м/с.
  За один физический кадр учитывается самый сильный удар, интервал урона — 0,5 с.
  Касательное движение вдоль стены само по себе не наносит урон.
- При 0 HP корпус исчезает, управление отключается, `GameManager` фиксирует поражение.
  Камера остаётся на месте; здоровье отображается в HUD, поражение — на панели результата.
- Перезапуск восстанавливает сцену и 100 HP.

### Доставки (milestone 2)

Три миссии выполняются последовательно. Подлетите к **оранжевому светящемуся
маяку** над площадкой: груз автоматически закрепится под дроном. Затем летите
к **зелёному светящемуся маяку** для доставки. Для взаимодействия нужно войти
в область 6 × 6 × 6 метров над площадкой (от уровня пола до высоты 6 метров).
Дополнительная кнопка не нужна. Неактивные площадки остаются цветными, но без маяка.

Чужая pickup-зона не выдаёт груз, чужая destination-зона его не принимает.
Доставка без груза невозможна. После третьей доставки фиксируется победа,
полёт останавливается. При уничтожении дрона груз убирается, доставки блокируются.
**R** полностью перезапускает уровень, восстанавливая HP и первую миссию.
Текущий этап задания отображается в HUD; победа и поражение — на панели результата.

| Миссия | Pickup (X, Z) | Destination (X, Z) |
| --- | --- | --- |
| 1 | −9, 18 | 18, −18 |
| 2 | 19, 12 | −20, −18 |
| 3 | −21, 0 | 0, 23 |

Добавлены два заполняющих источника света и маяки активных зон. Пол тёмный,
стены сине-серые, башни терракотовые, перекладина жёлтая, дрон голубой,
груз жёлтый с тёмной полосой. Существующий прожектор сохранён.

### Таймер, очки и сложность

Каждая миссия получает отдельный бюджет времени с момента её начала, включая
полёт к pickup. Следующая миссия начинает отсчёт заново. При 0 секунд наступает
поражение: груз убирается, управление и двигатели отключаются. При победе и
поражении таймер останавливается. Текущее время доступно в `TimeRemaining`;
HUD показывает оставшиеся секунды. Отладочный вывод таймера убран.

| Сложность | Время на миссию | Множитель урона от столкновений |
| --- | --- | --- |
| Easy | 120 с | ×0,5 |
| Normal (по умолчанию) | 75 с | ×1 |
| Hard | 45 с | ×1,5 |

`ScoreManager` начисляет очки только за успешную доставку:

```text
очки миссии = max(0, 500 + floor(оставшиеся секунды × 10) − потерянные HP × 15)
```

Штраф учитывает фактически потерянные HP с начала текущей миссии, включая
путь к грузу. Урон предыдущих миссий повторно не вычитается. Сумма очков
накапливается до конца попытки; неудавшаяся миссия очков не даёт. Формула одинакова
для всех сложностей, поэтому результаты разных сложностей напрямую не сравниваются.

Выбор сложности клавишами 1–3 сбрасывает прогресс, здоровье, таймер и очки.
R сохраняет выбранную сложность, но начинает новую попытку.
Выбор хранится только на время запущенной игры, без записи на диск.
В Inspector доступна `DifficultyManager.Level`.

### Визуальные эффекты

Четыре пропеллера вращаются через `PropellerAnimator`, а дочерние EngineFX
изображают двигатели. Pickup и delivery запускают оранжевые и зелёные вспышки.
Погода была удалена из текущего проекта; проверки удалённого WeatherManager
убраны из GameplayCheck. Новая модель управления не добавляет ветер.

HUD показывает здоровье, номер миссии, этап задания, груз, таймер, очки и сложность.

Параметры движения и урона доступны в Inspector у PlayerController.
GameManager и MissionManager принадлежат уровню; глобальные singleton-системы
пока не нужны. Маршруты задаются парами зон с одинаковым `MissionId` в узле `Zones`.
MissionManager выполняет их по возрастанию ID. У каждой миссии должна быть ровно
одна зона каждого типа. Cargo не меняет физику дрона и не имеет отдельного коллайдера.

## Проверка

```sh
dotnet build UniversityPractice.sln
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://Tests/MilestoneCheck.gd
godot --headless --path . --script res://Tests/DeliveryCheck.gd
godot --headless --path . --script res://Tests/GameplayCheck.gd
godot --headless --path . --script res://Tests/MovementCheck.gd
```

`godot` здесь — исполняемый файл Godot .NET. На macOS он может находиться по пути
`/Applications/Godot_mono.app/Contents/MacOS/Godot`.

Проверено: сборка без ошибок и предупреждений, импорт сцены, зависание, движение,
фактический урон от столкновения, обнуление HP, поражение и отключение управления.
DeliveryCheck дополнительно проверяет неверные зоны, доставку без груза,
закрепление груза, все три миссии, победу, блокировку после поражения и ввод R
с полным сбросом состояния.
GameplayCheck проверяет фактический урон 15/30/45 HP на трёх сложностях,
расчёт бонуса и штрафа, сброс таймера, поражение по времени,
эмиссию четырёх двигателей и сохранение сложности при R.
Автоматические тесты завершают процесс с сообщением `PASS` при успехе.
Визуальная оценка камеры и удобства управления требует запуска с окном.

Ручной сценарий: разгонитесь в стену, убедитесь в снижении HP в HUD;
отлетайте назад и повторяйте удары до поражения. Нажмите R и проверьте восстановление.
На малой скорости касания стены не должны наносить урон.

## Аркадный квадрокоптер: параметры управления

Параметры `PlayerController` доступны на узле `Player` в Inspector:

| Параметр | Начальное значение | Назначение |
| --- | --- | --- |
| `MaxHorizontalSpeed` | 12 м/с | Предел горизонтальной скорости, включая диагональ |
| `HorizontalAcceleration` | 18 м/с² | Ускорение WASD и изменение направления |
| `HorizontalDeceleration` | 14 м/с² | Торможение после отпускания WASD |
| `MaxClimbSpeed` | 4 м/с | Максимальная скорость подъёма |
| `MaxDescentSpeed` | 3 м/с | Максимальная скорость снижения |
| `VerticalAcceleration` | 8 м/с² | Плавность набора вертикальной скорости |
| `VerticalDeceleration` | 10 м/с² | Возврат к зависанию после отпускания вертикального ввода |
| `YawSpeed` | 1,8 рад/с | Скорость поворота Q/E |
| `MaxPitchAngle` | 18° | Максимальный визуальный pitch |
| `MaxRollAngle` | 22° | Максимальный визуальный roll |
| `TiltSpeed` | 8 с⁻¹ | Скорость сглаживания наклона; больше — быстрее |
| `TiltAltitudeLoss` | 0,25 м/с | Максимальная слабая просадка при сильном управляющем наклоне; 0 отключает |

Прежние `FlightSpeed`, `Acceleration`, `Deceleration`, `TurnSpeed`, `PitchAngle`,
`RollAngle`, `TiltSmoothingSpeed` заменены соответствующими именами из таблицы.
В текущих сценах переопределений этих старых параметров не было.

WASD задаёт ускорение в горизонтальных осях текущего yaw, а не мгновенную скорость.
При отпускании включается торможение без перехода через нулевую скорость.
Поворот носа меняет направление следующего ускорения, но не разворачивает накопленную
скорость мгновенно. При начальных значениях разгон до 12 м/с занимает около 0,67 с,
остановка — около 0,86 с и 5,1 м свободного пути. Вертикальная ось независима:
после отпускания Space/Shift скорость плавно достигает нуля без ручной компенсации гравитации.

Визуальный pitch/roll вычисляется из изменения горизонтальной скорости от управления
и торможения, до обработки столкновения. Ускорение вперёд наклоняет нос вниз,
торможение при движении вперёд — вверх; боковое торможение даёт обратный roll.
На постоянной предельной скорости без изменения направления управляющее ускорение
становится нулевым, и модель возвращается к нейтрали. Удар не создаёт резкого наклона.

Меняется только поворот `Visual`; физический root, коллайдер и камера не наклоняются.
Дочерние PropellerNE/NW/SE/SW продолжают собственное вращение. Cargo по-прежнему
крепится к Visual. Эмиссия всех четырёх двигателей прекращается при остановке игры.

Просадка берётся из величины **заданного** наклона и ограничивает добавку к целевой
вертикальной скорости. Отрисованный поворот Visual не участвует в физике.
При завершении манёвра просадка исчезает, и дрон снова зависает; возврат к прежней
высоте автоматически не выполняется. При нулевых углах или `TiltAltitudeLoss = 0`
эффекта нет. Ветер и аэродинамическая симуляция не добавлены.

После ручного полёта проверьте прежде всего `MaxHorizontalSpeed` и
`HorizontalDeceleration` (дистанция торможения), затем `HorizontalAcceleration`,
вертикальные скорости/торможение и `YawSpeed`. Визуальное ощущение регулируется
углами, `TiltSpeed` и `TiltAltitudeLoss`. Автотесты проверяют поведение, но не
субъективное удобство управления и точность доставки для игрока.

`Tests/MovementCheck.gd` проверяет разгон, торможение и обратный наклон, локальные
направления при разных yaw, лимиты скорости, зависание, просадку и её отключение,
изоляцию коллайдера/камеры, вращение пропеллеров и наличие экспортов для Inspector.

## Интерфейс и статистика

Меню содержит Start Game и Exit. После победы, уничтожения дрона или истечения
таймера показывается результат с кнопками Restart и Main Menu. Одно завершение
попытки обрабатывается GameManager ровно один раз; UI не определяет смерть
или выполнение миссии самостоятельно. Подписки снимаются при выходе из сцены.

В SessionStats время измеряется с загрузки уровня до его завершения, без времени
в меню. Damage events — количество случаев уменьшения HP, включая смертельный,
а не все касания стен. Доставки читаются из MissionManager. Restart создаёт новые
экземпляры состояния и сбрасывает показатели текущей попытки.

`user://statistics.json` содержит `totalRuns`, `totalWins`, `totalLosses`,
`totalDeliveries`, `bestCompletionTime` (секунды, null до первой победы).
Считаются только завершённые попытки: победы и поражения, включая таймаут.
Ранний R, смена сложности или закрытие игры без результата не увеличивают агрегаты.
Лучшее время сравнивается для всех сложностей вместе; это простая учебная статистика.

При отсутствии/повреждении JSON используются нулевые агрегаты. Ошибка чтения
выводит предупреждение. Запись идёт сначала во временный файл с последующей
заменой основного; ошибка записи не останавливает игру и видна в результате.
Открыть каталог: Godot → Project → Open User Data Folder.

UI построен стандартными Control/Container с anchors, общей стилизацией и
canvas_items stretch при базовых 1280×720. Узлы кэшируются при инициализации;
HUD обновляется 10 раз в секунду. Статистика записывается только при результате.

## Desktop export

Подготовлен preset **macOS**, результат `builds/DroneDelivery-macOS.zip`.
Templates на проверенной машине отсутствуют; экспорт приложения не выполнялся.

1. В Godot .NET 4.7.2 откройте Editor → Manage Export Templates и установите
   официальные export templates той же версии.
2. Создайте каталог `builds`, откройте Project → Export и выберите macOS.
3. Проверьте bundle identifier, выходной путь и .NET-параметры, затем Export Project.
4. Распакуйте архив и проверьте запуск `.app` вне редактора, Exit и статистику
   после повторного запуска. Preset не настроен для подписи/нотаризации; для
   распространения на другие Mac эти шаги нужно настроить отдельно.
5. Для Windows/Linux при необходимости создайте соответствующий preset в редакторе.

Тесты и документация исключены из экспортируемых ресурсов, `builds/` — из Git.
Никакой публикации, установки templates или сторонних сервисов не выполнялось.
